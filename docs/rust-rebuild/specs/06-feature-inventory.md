# 06 — User-Facing Feature Inventory (Parity Checklist)

Status: draft parity checklist for the Rust rewrite (CLI + TUI replacing the PyQt4 GUI, plus an `armoryd`-compatible daemon).
Source of truth: the Python 2 / C++ tree in this repository (Armory ~0.93, 2015). All `file:line` references are to the current checkout.

## How to read this document

* Every row is one user-visible capability (a menu item, button, dialog, context-menu action, RPC call, setting, CLI flag, background behaviour, or standalone tool). Each row has a stable ID (`WM-01`, `RPC-12`, ...) so the Rust project can track parity per row.
* **Location** is the defining class / method / line in the legacy code. The `Dlg*` classes live in `qtdialogs.py` unless another file is named.
* **Mode** says which user mode exposes the feature in ArmoryQt:
  * `S+` = Standard, Advanced and Expert (everyone)
  * `A+` = Advanced and Expert
  * `E` = Expert only
  * `daemon` = armoryd only; `CLI` = command-line flag; `bg` = automatic/background behaviour (no explicit UI control); `dev` = developer/standalone script.
  * Mode is switched under **User** menu (`ArmoryQt.py:642-674`, `setUserMode` `ArmoryQt.py:1809`) or Settings → *Preferred User Mode*; it is persisted as setting `User_Mode` (default `Advanced` on first run) and some aspects only apply after a restart.
* **Engine calls** names the backend (armoryengine / C++ BDM / SDM) entry points the feature relies on, so the Rust engine crates know what to expose. `TheBDM` = BlockDataManager (C++ via SWIG), `TheSDM` = Satoshi daemon manager (`SDM.py`), `wlt` = `PyBtcWallet` (`armoryengine/PyBtcWallet.py`).
* "Dormant" rows describe code that exists but is not reachable from the GUI in this build; they are listed so the rewrite can make an explicit keep/drop decision.

### Notable parity decisions surfaced by this inventory

* `sendtransaction` RPC (RPC-32) does not broadcast — it duplicates `gettransaction`.
* `armoryd.README` documents `getarmoryfunctions`; the implemented call is `help` (AD-10).
* Several settings are written but never read (`UnlockTimeout`, `DNAA_UnlockTimeout`, `AdvFeature_UseCt`), read but never written (`DispRmFee`, `DNAA_AllBackupWarn`, `DonateAlready`, `Excluded_Wallets`, `PrefEndian`, `SkipAnnounceCheck`), or shown but not saved (`SkipVersionCheck`).
* Plugins load only on testnet as unsigned `.py` files; the signed-zip path is disabled (PL-01/PL-02).
* Addresses-menu "Import/Sweep Private Key" items only show an explanatory message; the real feature lives in Wallet Properties (MI-02, AR-07/AR-08).
* Wallet-recovery mode selection is available to all user modes (Expert-only gating is commented out) (WM-17).
* Everything Qt-specific (printing via QPrinter, clipboard, system tray, registry/gconf URI registration, splash screen, window geometry) needs a CLI/TUI-appropriate substitute rather than a literal port.
